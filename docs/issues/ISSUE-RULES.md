# 이슈 파일 작성 규칙

이 문서는 `docs/issues/` 디렉터리에 이슈를 기록하는 방식을 정의합니다.  
Claude가 이슈를 생성하거나 업데이트할 때 이 규칙을 따릅니다.

---

## 디렉터리 구조

```
docs/issues/
├── ISSUE-RULES.md                              ← 이 파일 (규칙 문서)
├── ISSUE-INDEX.md                              ← 전체 이슈 목록 대시보드
├── ISSUE-001-2026-11-09-제목.md
├── ISSUE-002-2026-11-17-제목.md
└── ...
```

---

## 네이밍 컨벤션

```
ISSUE-{NNN}-{YYYY-MM-DD}-{짧은-설명}.md
```

- `NNN`: 3자리 숫자, 001부터 순차 증가
- `YYYY-MM-DD`: 이슈 **생성일**
- 짧은 설명: 영어 소문자 + 하이픈, 최대 5단어
- 예: `ISSUE-001-2026-11-09-windows-korean-spellcheck.md`

---

## ISSUE-INDEX.md 구조

전체 이슈를 한눈에 볼 수 있는 대시보드 파일.  
이슈 생성/상태 변경 시 반드시 함께 업데이트한다.

```markdown
| 번호 | 제목 | 진행도 | 내용 | 테스트 결과 |
|------|------|--------|------|------------|
| [ISSUE-001](파일경로) | 제목 | open | 한줄 요약 | - |
```

**컬럼 정의:**

| 컬럼 | 설명 |
|------|------|
| 번호 | 파일 링크 포함 (`[ISSUE-NNN](파일명)`) |
| 제목 | 이슈 제목 (한국어) |
| 진행도 | `open` / `in-progress` / `resolved` / `deferred` / `closed` |
| 내용 | 문제 현상 한 줄 요약 |
| 테스트 결과 | 수정 후 검증 결과. 미검증이면 `-` |

---

## 이슈 파일 템플릿

```markdown
# ISSUE-NNN: 제목

**상태:** open | in-progress | resolved | deferred | closed  
**우선순위:** high | medium | low  
**유형:** bug | improvement | feature | question  
**생성일:** YYYY-MM-DD  
**수정일:** YYYY-MM-DD  

## 문제 설명

(현상, 발생 조건, 영향 범위를 간결하게)

## 원인 분석

(알고 있는 경우 작성, 모르면 "미파악"으로 표시)

## 해결 방안

### 현재 적용 (임시/부분 해결)

(적용된 내용, 파일, 이유)

### 추후 개선 (TODO)

(더 완전한 해결책, 조건, 우선순위)

## 테스트 결과

(수정 후 검증 내용. 미검증이면 "미검증"으로 표시)

## 참고

(관련 링크, 파일 경로, 외부 문서 등)
```

---

## 상태 값 정의

```
open → in-progress → resolved → closed
                  ↘ deferred
```

| 상태 | 의미 |
|------|------|
| `open` | 미해결, 아직 작업 시작 전 |
| `in-progress` | 현재 작업 중 |
| `resolved` | 코드 반영 완료, 실제 동작 테스트 대기 |
| `deferred` | 의도적으로 뒤로 미룸 (조건 명시 필요) |
| `closed` | 테스트까지 완료된 최종 해결 상태 |

## 유형 값 정의

| 유형 | 의미 |
|------|------|
| `bug` | 기능이 의도대로 동작하지 않음 |
| `improvement` | 기존 기능의 UX/시각적 개선 |
| `feature` | 새로운 기능 추가 |
| `question` | 동작 방식 확인 또는 정책 결정 필요 |

---

## 운영 규칙

1. **새 이슈 생성 시** — 파일 생성 후 `ISSUE-INDEX.md`도 즉시 업데이트
2. **상태 변경 시** — 이슈 파일과 `ISSUE-INDEX.md` 동시 업데이트, 수정일 갱신
3. **코드 반영 완료 시** — 상태를 `resolved`로, 테스트 결과란에 "테스트 대기" 기재
4. **테스트 완료 시** — 상태를 `closed`로, 테스트 결과란에 검증 내용 기재
5. **부분 해결 시** — 상태를 `deferred`로, "현재 적용"과 "추후 개선" 분리 기재
6. **이슈 번호 재사용 금지** — closed 이슈 번호는 영구 보존
