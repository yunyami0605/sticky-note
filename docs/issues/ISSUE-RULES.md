# 이슈 파일 작성 규칙

이 문서는 `docs/issues/` 디렉터리에 이슈를 기록하는 방식을 정의합니다.  
Claude가 이슈를 생성하거나 업데이트할 때 이 규칙을 따릅니다.

---

## 디렉터리 구조

```
docs/issues/
├── ISSUE-RULES.md        ← 이 파일 (규칙 문서)
├── ISSUE-001-제목.md
├── ISSUE-002-제목.md
└── ...
```

---

## 네이밍 컨벤션

```
ISSUE-{NNN}-{짧은-설명}.md
```

- `NNN`: 3자리 숫자, 001부터 순차 증가
- 짧은 설명: 영어 소문자 + 하이픈, 최대 5단어
- 예: `ISSUE-001-windows-korean-spellcheck.md`

---

## 이슈 파일 템플릿

```markdown
# ISSUE-NNN: 제목

**상태:** open | in-progress | deferred | closed  
**우선순위:** high | medium | low  
**생성일:** YYYY-MM-DD  
**수정일:** YYYY-MM-DD  

## 문제 설명

(현상, 발생 조건, 영향 범위를 간결하게)

## 원인 분석

(알고 있는 경우 작성, 모르면 "미파악"으로 표시)

## 해결 방안

### 현재 적용 (임시/부분 해결)

(적용된 내용, 파일, 이유)

### 추후 개선 (TODO)

(더 완전한 해결책, 조건, 우선순위)

## 참고

(관련 링크, 파일 경로, 외부 문서 등)
```

---

## 상태 값 정의

| 상태 | 의미 |
|------|------|
| `open` | 미해결, 아직 작업 시작 전 |
| `in-progress` | 현재 작업 중 |
| `deferred` | 의도적으로 뒤로 미룸 (조건 명시 필요) |
| `closed` | 해결 완료 |

---

## 운영 규칙

1. **새 이슈 발견 시** — Claude가 즉시 파일 생성, 번호는 기존 최대값 + 1
2. **부분 해결 시** — 상태를 `deferred`로, "현재 적용"과 "추후 개선" 분리 기재
3. **완전 해결 시** — 상태를 `closed`로 변경, 수정일 갱신
4. **수정일** — 파일을 편집할 때마다 오늘 날짜로 갱신
5. **이슈 번호 재사용 금지** — closed 이슈 번호는 영구 보존
